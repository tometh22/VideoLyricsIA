# Browser E2E tests

These tests run the real Vite/React application in headless Chromium. The
editor API is mocked at the browser boundary and the audio URL resolves to a
synthetic WAV generated by `e2e/editor-harness.js`, so the suite is deterministic
and does not require staging credentials or a running backend.

From `lyricgen/frontend`:

```bash
npm run test:e2e:install   # once per machine/CI image
npm run test:e2e
```

Useful variants:

```bash
npx playwright test --headed
npm run test:e2e:ui
PLAYWRIGHT_CHANNEL=chrome npm run test:e2e
```

CI should run `npm run test:e2e:install` before `npm run test:e2e` and publish
`test-results/` when a retry or trace is needed. The default project is the
Playwright-bundled Chromium build; setting `PLAYWRIGHT_CHANNEL=chrome` uses the
locally installed Google Chrome channel instead.

## Known baseline gaps

Two tests are intentionally marked `fixme` rather than hidden:

- the real ruler click does not currently update `audio.currentTime` in the
  Chromium run;
- a real block-to-block marquee drag does not expose the expected selection
  count, while Cmd/Ctrl-click selection and group movement do pass.

When the product interaction is corrected, remove the two `test.fixme` lines in
`e2e/lyrics-editor.spec.js`; the scenarios are already implemented and will
become required CI coverage.
